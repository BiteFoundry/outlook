# v0.3.0 — Microsoft OneNote

Version `0.3.0` adds Microsoft OneNote as a third persona. The single unified binary still provides all three: `teams`, `outlook` and `onenote`.

## Persona

- New `onenote` persona in the same binary as `teams` and `outlook`.
- Select it with `TEAMS_PERSONA=onenote` (or `note`), or by invoking the binary through an `onenote` launcher, which resolves the persona from the `argv[0]` stem.

## TUI

- New `Notes` tab (7th tab, `Ctrl+8`) browsing personal and team/group notebooks, section groups and sections.
- Section ribbon bar above the page list for switching sections.
- Page list column with authentic OneNote subpage indentation (levels 0, 1 and 2+); on narrow terminals it collapses to a compact active-page selector.
- Rich page canvas: headings, nested ordered/unordered lists, quotes, Unicode box-drawn tables, bordered code blocks with a language badge, colored tags (`★`, `❓`, `❗`, highlight) and interactive `☐`/`☑` to-do checkboxes.

## Composition

- Create a notebook (`B`), a section (`S`), and a page or subpage (`n` / `N`).
- Append Markdown to the end of a page (`a`).
- Edit a single block with `e`, pre-filled with that block's Markdown.
- Markdown `- [ ]` task items are supported on create and append, and can be toggled from the canvas or with the `check` command.

## Images and attachments

- Inline images and `<object>` attachments are rendered as chips in the page canvas, with inline image thumbnails drawn in the terminal and cached.

## CLI

```
onenote notebooks|sections|pages|read|create-notebook|create-section|create|append|update|check|delete|search|resource
```

- `read` supports `--format md|plain|blocks|xhtml` and `--preview-images`.
- `create` and `append` accept `--file` and repeatable `--image`.
- `update` targets a whole page or a single `--block-id`; `check` toggles a to-do by `--block-id` or `--index`.
- `search` queries the local SQLite FTS5 index (`onenote_fts`).

## HTTP JSON API

- Routes under `/v1/onenote`, also mounted unversioned as `/onenote`:

```
GET  /v1/onenote/notebooks
POST /v1/onenote/notebooks
GET  /v1/onenote/sections
POST /v1/onenote/sections
GET  /v1/onenote/sections/{section_key}/pages
POST /v1/onenote/sections/{section_key}/pages
GET  /v1/onenote/pages/{page_key}
PATCH /v1/onenote/pages/{page_key}
DELETE /v1/onenote/pages/{page_key}
POST /v1/onenote/pages/{page_key}/append
POST /v1/onenote/pages/{page_key}/toggle-todo
GET  /v1/onenote/search
```

## MCP

Ten `onenote_*` tools are available over the stdio MCP server:

- `onenote_list_notebooks`, `onenote_list_sections`, `onenote_list_pages`
- `onenote_get_page`, `onenote_create_page`, `onenote_append_page`
- `onenote_update_page`, `onenote_toggle_todo`
- `onenote_search`, `onenote_delete_page`

## OAuth

- OneNote requests the `Notes.ReadWrite` and `Notes.ReadWrite.All` scopes.

## Known limitations

- No HTTP or MCP attachment download yet; page resources can be downloaded or previewed only through the CLI `onenote resource`.
- OneNote media send is not live-verified against a real tenant.
